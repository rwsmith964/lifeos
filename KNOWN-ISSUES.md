## Fixed and verified live this pass (round 2, D-033 — Phase 2, custody)

Migration `20260820000019_custody_schedules.sql` applied live. Multi-day custody blocks now render on every day they span, not just the start date (was actually two bugs: a query that never fetched blocks starting before the visible window, plus a calendar page that only indexed the start day — both fixed). Every custody item on the calendar now shows who-with-whom (`"Emma Smith with Jen"`), not just a bare label. Handover time is a real field end to end (one-off form and the new schedule materializer both use it) — the old hardcoded 5pm is gone. `/calendar/custody` is a new schedule hub (list, create, delete); `/calendar/custody/new` is a recurrence editor (named-preset or fully custom cycle, with a live 14-day preview and gap warnings before saving); the calendar gained a `view=custody` toggle with a per-child color legend. The responsible-parent picker (both the one-off form and the schedule editor) now excludes grandparents, offering only `self`/`co_parent`/`spouse`/`partner`. See D-033 for the full design and the live verification steps run against production.

## Fixed and verified live this pass (round 2, D-034 — AI features now actually functional)

`ANTHROPIC_API_KEY` is set in Vercel. Getting a real key live immediately surfaced two previously-invisible RLS/wrong-client bugs (the health-gating from D-032 could only prove the *absence* of a key was handled gracefully, never that a *present* key actually worked) — both fixed, see D-034: `ai_usage_log` writes (used by all three AI features) and `weekend_plans` writes were both being attempted with the request-scoped user client against tables that, by design, only a service-role client can write.
